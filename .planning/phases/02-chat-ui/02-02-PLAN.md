## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| GET /api/history response → innerHTML | History entries from SQLite (user-originated content) rendered into the feed via buildHistoryCard; all user fields must pass through escHtml() |
| POST /api/ask response → innerHTML | AI-generated SQL and error messages rendered into the feed via buildHistoryCard; renderSqlBox and renderTable handle escaping internally |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-02-06 | Tampering / XSS | loadHistory() — renders all history entries from GET /api/history via buildHistoryCard | mitigate | buildHistoryCard calls escHtml(entry.question) and escHtml(entry.error) (implemented in Plan 01); renderSqlBox and renderTable escHtml internally |
| T-02-07 | Tampering / XSS | ask() — error path renders data.error and data.message from API response | mitigate | errMsg is passed into buildHistoryCard's entry.error field; escHtml(entry.error) is called inside buildHistoryCard body |
| T-02-08 | Tampering / XSS | clearHistory() — restored empty-state HTML is a literal constant | accept | No user data injected; the empty-state HTML is a static string literal with no dynamic fields |
| T-02-09 | Denial of Service | loadHistory() crashes if GET /api/history is unavailable or returns non-array | mitigate | Entire loadHistory() body wrapped in try/catch; error is console.error'd only; feed remains in empty-state, query functionality is unaffected |
| T-02-SC | Tampering | npm/pip/cargo installs | accept | D-12 mandates zero new npm dependencies — no package installs in this phase |
</threat_model>
