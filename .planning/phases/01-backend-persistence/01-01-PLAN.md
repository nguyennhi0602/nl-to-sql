## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| NestJS DI container → DatabaseService | Internal trust; DatabaseService is a singleton; no external input crosses here |
| INSERT statement ← save() parameters | Data originates from Groq API response and SQLite execute() output — not directly from user input at this layer, but the question field originated as user text |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-01-01 | Tampering | query_history DDL in initHistory() | mitigate | Use CREATE TABLE IF NOT EXISTS — idempotent, no destructive ALTER; table schema locked at creation |
| T-01-02 | Information Disclosure | HistoryService.findAll() | accept | Single-user app, no auth scope; all history belongs to the same implicit user; no PII beyond what the user already queried |
| T-01-03 | Denial of Service | Unbounded rows storage | mitigate | MAX_STORED_ROWS = 100 cap applied via slice before INSERT — per D-04; large result sets cannot bloat the DB |
| T-01-04 | Tampering | JSON serialization round-trip | accept | Buffer/BigInt edge cases exist (Pitfall 6) but seeded schema has no BLOB columns; low immediate risk; sanitiseRow helper deferred to v2 per HIST-V2-03 |
| T-01-SC | Tampering | npm/pip/cargo installs | accept | D-05 mandates zero new dependencies; no package-manager installs in this plan |
</threat_model>
