<task type="checkpoint:human-action" gate="blocking">
  <name>Task 1: Create Vercel project, set root directory, connect Neon Postgres, set env vars</name>
  <what-built>Plans 03-01 through 03-03 produced a deployable NestJS backend with dual-driver database, api/index.ts serverless entry point, and vercel.json. This task connects that code to Vercel.</what-built>
  <how-to-verify>
    Complete all steps in order:

    **Step 1 — Create Vercel account (if not already done)**
    - Go to https://vercel.com/signup
    - Sign in with GitHub (recommended — links the account automatically)

    **Step 2 — Import the GitHub repo**
    - Vercel dashboard → click "Add New..." → "Project"
    - Select GitHub → find nguyennhi0602/nl-to-sql → click "Import"

    **Step 3 — Set Root Directory BEFORE deploying**
    - In the "Configure Project" screen, expand "Root Directory"
    - Type: `backend` (exactly, no slash)
    - This is CRITICAL — without it, Vercel looks for package.json at the repo root and the build fails

    **Step 4 — Set Framework Preset**
    - Vercel may auto-detect NestJS. If so, keep it.
    - If not detected, set Framework Preset to "Other" — vercel.json handles the build config.

    **Step 5 — Do NOT deploy yet** — click "Deploy" only after env vars are set (Step 8)

    **Step 6 — Add Neon Postgres database**
    - Go to the Vercel dashboard for the project you just created
    - Click "Storage" tab → "Browse Marketplace" → find "Neon" → click "Add"
    - Follow Neon's setup flow to create a new Postgres database
    - After creation, Neon injects several env vars automatically. Find DATABASE_URL in the list — it will contain `-pooler.` in the hostname (this is the PgBouncer pooled URL required by @vercel/postgres)
    - Copy the DATABASE_URL value

    **Step 7 — Verify DATABASE_URL contains -pooler.**
    - The copied value must look like: `postgresql://user:password@ep-XXXX-pooler.region.aws.neon.tech/dbname?sslmode=require`
    - If it contains `-pooler.` in the host → correct, proceed
    - If it does NOT contain `-pooler.` (direct connection) → use DATABASE_URL_UNPOOLED as the fallback, but check if Neon provides a separate pooled URL in the env vars list

    **Step 8 — Set environment variables**
    - Vercel project → Settings → Environment Variables
    - Add: `GROQ_API_KEY` = (value from backend/.env file)
    - Verify: `DATABASE_URL` is already present (auto-injected by Neon in Step 6). If not, add it manually with the pooled connection string from Step 6.
    - Confirm both variables are set for "Production", "Preview", and "Development" environments

    **Step 9 — Trigger first deployment**
    - Go back to the project → Deployments → click "Redeploy" (or push a commit to trigger it)
    - Watch the build log — the build command `npm run build` should run and succeed
    - If build fails:
      - "Cannot find module '../src/app.module'" → add `.js` extension to the import in backend/api/index.ts, commit, push
      - "bundle size too large" → check if better-sqlite3 native binary is bundled; see Pitfall 5 in RESEARCH.md

    **Step 10 — Verify first deployment succeeds**
    - Deployment status shows "Ready" (green checkmark)
    - Note the production URL (e.g., https://nl-to-sql-XXXX.vercel.app)
  </how-to-verify>
  <resume-signal>Paste the production Vercel URL when deployment is ready (e.g., "https://nl-to-sql-XXXX.vercel.app"), or describe any errors encountered</resume-signal>
</task>
