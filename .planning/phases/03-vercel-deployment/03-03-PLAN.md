  <action>
    Create the file backend/api/index.ts. The directory backend/api/ does not exist yet — create it.

    The file implements the NestJS app singleton pattern from RESEARCH.md Pattern 2. Key requirements:
    - NestApp is initialized ONCE per cold start (module-scope initPromise, not per-request)
    - The express instance is created at module scope (before the handler is invoked)
    - The handler awaits initialization before delegating to the express app
    - CORS is enabled on the NestJS app
    - The default export is the handler function (not a named export)

    Implementation:
    ```typescript
    import { NestFactory } from '@nestjs/core';
    import { ExpressAdapter } from '@nestjs/platform-express';
    import express, { type Express } from 'express';
    import { AppModule } from '../src/app.module';

    const expressApp: Express = express();
    let nestReady = false;
    let initPromise: Promise<void> | null = null;

    function init(): Promise<void> {
      if (!initPromise) {
        initPromise = NestFactory.create(AppModule, new ExpressAdapter(expressApp))
          .then(async (app) => {
            app.enableCors();
            await app.init();
            nestReady = true;
          });
      }
      return initPromise;
    }

    export default async function handler(req: any, res: any): Promise<void> {
      if (!nestReady) await init();
      expressApp(req, res);
    }
    ```

    IMPORT PATH NOTE (per Pitfall 6 and Assumption A1):
    - Use `'../src/app.module'` WITHOUT the .js extension as the first attempt
    - tsconfig.json uses "module": "nodenext" which technically requires .js extensions for ESM
    - However, Vercel compiles api/index.ts with its own toolchain (not tsc), so the extension may be optional
    - If the first deploy fails with "Cannot find module '../src/app.module'", the fallback is to add '.js' extension
    - Document this assumption in the SUMMARY

    SERVESTATIC NOTE: AppModule includes ServeStaticModule. This is intentional — it serves public/ during local dev. On Vercel, the CDN serves /public/index.html before the function is reached (per vercel.json rewrites), so ServeStaticModule is harmlessly bypassed. Do NOT remove ServeStaticModule from AppModule.

    The handler is typed as (req: any, res: any) to be compatible with both Vercel's VercelRequest/VercelResponse types and Express's req/res types without requiring a @vercel/node type import at the handler level.
  </action>

    CREATE backend/vercel.json:

    The Vercel project root will be set to backend/ in the dashboard (Plan 03-04 manual step). So vercel.json is relative to backend/.

    Use the following configuration:
    ```json
    {
      "$schema": "https://openapi.vercel.sh/vercel.json",
      "buildCommand": "npm run build",
      "outputDirectory": "public",
      "rewrites": [
        { "source": "/api/:path*", "destination": "/api/index" },
        { "source": "/:path*", "destination": "/index.html" }
      ]
    }
    ```

    Rationale for each field:
    - buildCommand: "npm run build" — runs nest build which compiles src/ to dist/
    - outputDirectory: "public" — tells Vercel CDN to serve backend/public/ as the static root; index.html is at the root of this directory
    - rewrites:
      - "/api/:path*" → "/api/index" — routes all /api/* requests to the serverless function at backend/api/index.ts
      - "/:path*" → "/index.html" — SPA fallback: all non-API routes serve index.html from the CDN output

    NOTE on outputDirectory (Assumption A2): Using "public" means Vercel serves files from backend/public/ directly. The second rewrite "/:path*" → "/index.html" handles the SPA routing. Since there is only one HTML file, this is straightforward.

    UPDATE backend/tsconfig.json:

    Add an "include" array to ensure the api/ directory is covered by TypeScript:
    ```json
    "include": ["src/**/*", "api/**/*", "test/**/*"]
    ```

    The current tsconfig.json has no "include" key, so TypeScript currently picks up everything not excluded. Adding an explicit "include" is safer and makes the intent clear. Add it as a top-level key alongside "compilerOptions".

    IMPORTANT: Do NOT modify "compilerOptions" in tsconfig.json — particularly do not change "module": "nodenext". Vercel's TS compiler reads this file; the nodenext setting is required for the project.

    Do NOT modify tsconfig.build.json (if it exists) — nest build uses that file and it intentionally excludes api/ (Vercel compiles api/index.ts independently).
  </action>
