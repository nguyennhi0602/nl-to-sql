<objective>
Rewrite DatabaseService with a dual-driver architecture: SQLite (better-sqlite3) for local development, Vercel Postgres (@vercel/postgres) for production. The switch is controlled exclusively by the DATABASE_URL environment variable — if set, use Postgres; if absent, use SQLite. All public methods return Promise<T> on both paths so callers never need driver-specific branching.

Purpose: This is the foundation of the entire deployment. Without a database that works on Vercel, the app cannot persist history across cold starts (DEPLOY-02). The async-everywhere contract makes the HistoryService and controller migrations in Plan 03-02 straightforward.

Output: Updated package.json with @vercel/postgres, rewritten database.service.ts with dual-driver onModuleInit, async public API, PostgreSQL DDL equivalents, and a package legitimacy checkpoint before npm install.
</objective>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| env → DatabaseService | DATABASE_URL and GROQ_API_KEY flow from Vercel env vars into process.env; never committed |
| DatabaseService → Neon Postgres | All queries go through @vercel/postgres pool; parameterized queries prevent injection |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-03-01 | Tampering | DatabaseService.query() | mitigate | All Postgres queries use $1,$2,... parameterized form via pool.query(sql, params) — no string interpolation of user data |
| T-03-02 | Information Disclosure | process.env.DATABASE_URL | mitigate | DATABASE_URL read at runtime from env only; never logged (confirm no console.log(process.env) in service); .env in .gitignore |
| T-03-03 | Tampering | seedPg() INSERT data | accept | Seed data is hardcoded literals, no user input; no injection surface |
| T-03-SC | Tampering | npm install @vercel/postgres @vercel/node | mitigate | Task 1 checkpoint blocks install until human verifies both packages on npmjs.com |
</threat_model>
